# UI・ダイアログ監査報告（2026-07-20）

## 目的

設定画面や各種ポップアップを中心に、日本語・英語表示、画面寸法、終了操作、ウィンドウ位置復元、文言の一貫性を確認した。

監査時点ではUIコードを修正していなかった。監査時点のブランチは `codex/ui-dialog-audit`、基準コミットは `d77e07b`（`chore: release v0.9.48`）である。下記「修正状況」へ、その後の対応を追記する。

## 修正状況

- タイトル画面編集の終了方法の不整合は修正済み。`OK` は変更を保持し、キャンセル・右上の×・Escはすべてダイアログを開いた時点へ復元する。
- 実質的な確定処理を持たなかった「適用」ボタンはタイトル画面編集から削除した。
- メモリ上の実ROMデータを使用し、OK、キャンセル相当、右上の×、Escを個別に検査した。
- 画面外位置の復元防止は修正済み。現在の全画面と交差しない保存位置は親画面または主画面の中央へ戻し、一部だけ外れる位置と過大な保存サイズは現在の作業領域内へ補正する。
- 左または上に配置したモニターの負座標を保存できるようにし、設定、改造設定、統計、ピクセル編集、スプライトビューア、キーボードマップ、元に戻す履歴の個別処理も共通補正へ接続した。
- 設定、ボーナスステージ、パレット、ピクセル編集、スプライトビューア、タイトル画面編集の横幅を修正済み。1600px幅で収まらなかった対象は、日英とも1600px未満になった。
- 標準ダイアログボタンは共通処理へ統一済み。日本語では `OK / キャンセル / 適用 / 閉じる`、英語では `OK / Cancel / Apply / Close` と表示する。
- 監査で確認した翻訳処理外の操作文言は日英辞書へ接続済み。タイトル画面のエンディング表示、列名、条件、配置数、NES 64色、パレットの面範囲、ミラーのPhase表記を対象とした。

## 確認方法

- 主要19ダイアログを日本語・英語の両方でオフスクリーン生成
- 各ダイアログの初期寸法、最小寸法、サイズヒントを取得
- 実際の接続画面（2560x1392、1600x1152の作業領域）と比較
- 標準ボタンの表示文言を日本語・英語で取得
- ウィンドウ位置復元処理へ画面外座標を与えて挙動確認
- タイトル画面編集のキャンセル、直接reject、右上の閉じる操作をメモリ上のROMコピーで比較
- 翻訳辞書の日英エントリ欠落と、翻訳処理を通らない直接指定文言を静的確認
- `python -B -m unittest discover -s magatu_skc\core\tests -p "test_*.py"` を実行

ROMファイルの生成、上書き、変更は行っていない。

## 結論と優先順位

### 1. 最優先：タイトル画面編集の終了方法によって結果が変わる

対応済み。以下は監査時点で確認された修正前の状態である。

対象: `magatu_skc/ui/title_screen_dialog.py`

- 「キャンセル」ボタンは `_on_cancel()` を通り、ダイアログを開いた時点のROM内容へ復元する。
- 右上の×やEsc相当の `reject()` は `_on_cancel()` を通らず、編集内容を残したまま閉じる。
- 実測結果は、直接 `reject()` した場合は復元されず、`_on_cancel()` を呼んだ場合だけ復元された。
- 「適用」はROMへの確定処理ではなく、変更がすでにメモリ上へ反映されていることを知らせるだけである。
- 「適用」の後に「キャンセル」を押すと、適用前ではなくダイアログを開いた時点まで全変更が戻る。

同じ画面でも閉じ方によって保存結果が変わり、「適用」の一般的な意味とも一致しない。誤操作による変更消失、または意図しない変更保持につながる。

改善案:

- 右上の×、Esc、キャンセルを同じ終了処理へ統一する。
- 現在の編集方式を維持するなら、実質的な確定処理を持たない「適用」を削除し、`OK / キャンセル` に整理する。
- 「適用」を残す場合は、適用時点を新しい復元基準として更新し、それ以前の変更を後のキャンセルで戻さない仕様にする。

### 2. 高：狭い画面に収まらないダイアログがある

対応済み。以下は監査時点で確認された修正前の状態である。

1600x1152の作業領域に対する確認結果:

| 言語 | ダイアログ | 必要幅 | 判定 |
|---|---|---:|---|
| 日本語 | ボーナスステージ編集 | 1804px | 横にはみ出す |
| 日本語 | パレット編集 | 1624px | 横にはみ出す |
| 英語 | ボーナスステージ編集 | 1804px | 横にはみ出す |
| 英語 | 16x16ピクセル編集 | 2022px | 横にはみ出す |
| 英語 | パレット編集 | 1624px | 横にはみ出す |
| 英語 | スプライトビューア | 2232px | 横にはみ出す |
| 英語 | タイトル画面編集 | 1853px | 横にはみ出す |

設定画面の英語表示も最小幅1493pxであり、1600px画面には収まるものの余裕がほとんどない。一般的な1366px幅の画面には収まらない。

主な原因:

- ボーナスステージ編集は32位置を1行4組、合計16グリッド列で固定配置している。
- パレット編集は壁色を1行6組で固定し、操作ボタンも横一列に配置している。
- スプライトビューアは横スクロールバーを明示的に無効化している。
- 設定画面の「一般」タブには全体スクロールがなく、英語の長いラベルや入力欄が最小幅を押し広げる。
- ピクセル編集とタイトル画面編集は、プレビューと操作欄の横並び、および英語の長い説明が最小幅を押し広げる。

改善案:

- ダイアログ全体、または幅を必要とする主要部分へスクロール領域を設ける。
- 固定の横並び数を減らすか、利用可能幅に応じて折り返す。
- スプライトビューアで横スクロールを利用できるようにする。
- 設定画面の「一般」タブもスクロール可能にし、長い説明は折り返す。

修正後のオフスクリーン再計測では、問題対象の最大幅は日本語1234px、英語1234pxとなった。個別には、設定700px、ボーナス800px、パレット800px、ピクセル編集は日本語760px・英語1081px、スプライトビューア760px、タイトル画面編集1234pxである。幅を必要とする内容は内部スクロールで操作できる。

### 3. 高：保存されたウィンドウ位置が画面外でも復元される

対応済み。以下は監査時点で確認された修正前の状態である。

対象: `magatu_skc/ui/dialog_geometry.py` および同等処理を個別実装しているダイアログ。

- 保存座標 `5000,5000` を与えたところ、そのまま画面外へ復元された。
- モニターを外した場合、解像度を変更した場合、リモートデスクトップ等で画面構成が変わった場合に、ダイアログを操作できなくなる可能性がある。
- 共通保存処理はX/Yを0以上へ丸めるため、メイン画面の左側または上側に置かれたモニターの正当な負座標を保存できない。
- 設定、ピクセル編集、スプライトビューア、統計、キーボードマップ等には類似した位置復元処理が個別に存在する。

改善案:

- 保存位置とサイズを、現在接続されている全画面の作業領域と照合する。
- どの画面とも交差しない場合は、親画面または主画面の中央へ戻す。
- 負座標を禁止せず、実在する画面の作業領域内ならそのまま保存・復元する。
- 個別実装を共通ヘルパーへ寄せ、同じ補正をすべてのダイアログへ適用する。

共通処理へ、全画面との交差判定、画面内へのサイズ・位置補正、完全な画面外位置の中央復帰を実装した。保存時の負座標も維持する。自動テストでは、`5000,5000` の画面外位置、画面より大きい保存サイズ、負座標の保存を個別に検査している。

### 4. 中：日本語UIに英語の標準ボタンが混在する

対応済み。以下は監査時点で確認された修正前の状態である。

日本語表示でも次の画面に `Cancel`、`Apply`、`Close` が残る。

- 設定
- ボーナスステージ編集
- ROM検証結果
- 改造設定
- パレット編集
- ミラー編集
- スプライトビューア
- 特殊処理
- タイトル画面編集

一方、敵ドロップ、デモ入力、クリアメッセージ、サウンドビューア等は日本語化されており、画面ごとに表記が異なる。

改善案:

- 標準ボタンを作る共通処理を用意し、日本語では `OK / キャンセル / 適用 / 閉じる`、英語では `OK / Cancel / Apply / Close` に統一する。

全ての `QDialogButtonBox` を共通の標準ボタン翻訳処理へ接続した。主要19ダイアログを日英で再生成し、日本語・英語とも各標準ボタンが指定どおり表示されることを確認した。

### 5. 中：翻訳処理を通らない英語文言が残る

対応済み。以下は監査時点で確認された修正前の状態である。

翻訳辞書の日英エントリそのものに欠落はなかった。ただし、UIコードへ直接書かれて翻訳辞書を通らない表示がある。

確認例:

- パレット編集の `Stages`
- ミラー編集の `Phase 1`
- タイトル画面のエンディング編集にある `View / Line / Text / Count`
- エンディング表示種別の `True Ending / Good Ending / Bad Ending / Worst Ending`
- タイトル色編集系の `NES 64 Colors`

ゲーム固有名として英語を残す項目と、操作説明として翻訳する項目を分けたうえで、操作用文言は翻訳辞書へ移す必要がある。

上記の操作用文言に加え、エンディング条件、タイトル上のキャラクター配置数、プレビュー取得失敗表示も翻訳辞書へ接続した。`Phase`、`NES`、エンディング種別などのゲーム・技術用語は日英で意味を変えず、周辺の操作文言を各言語へ揃えた。

## 問題が確認されなかった項目

- 主要19ダイアログは、日本語・英語とも生成時例外なく構築できた。
- 翻訳辞書には、`ja` または `en` が欠落した登録はなかった。
- 既存テスト117件はすべて成功した。

ただし、既存テストは今回確認したウィンドウ寸法、画面外復元、右上の×とキャンセルの差、標準ボタンの表示言語を検査していない。

## 推奨修正順

1. タイトル画面編集の×・Esc・キャンセル・適用の意味を統一
2. ボーナス、パレット、ピクセル、スプライト、タイトル、設定の可変幅・スクロール対応（対応済み）
3. 全ダイアログの画面外復元防止を共通化（対応済み）
4. 標準ボタンと直接指定英語文言の日英統一（対応済み）
