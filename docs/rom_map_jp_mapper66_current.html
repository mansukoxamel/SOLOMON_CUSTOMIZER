0. 運用ルール

このHTMLをROM台帳の唯一のマスターとし、実装側予約スパンと同時に正とする。
PRG0専用台帳、監査表、候補表などでROM予約を二重管理しない。空き候補・非常用候補もこのHTMLに集約する。
新しいROM領域を使う前に、このHTML、docs/ram_map_current.html、実装側の RESERVED_SPANS / OFF_* / CPU_* 定数を確認する。 予約の追加・移動・解除をしたら同じ変更でこの表も更新する。重複、古い名前、根拠不明の「空き候補」が残っている状態ではリリース不可。 原作ROMで 00 や EA が並ぶ領域でも、既にモジュールが上書きしている場所は空き扱いしない。 完成形runtimeは、ステージ内容や使用敵の有無で書いたり書かなかったりしない。保存ROMの構造を固定し、差分・重複・巻き込み事故を防ぐため、未使用でも毎回同じ配置へ書く。
