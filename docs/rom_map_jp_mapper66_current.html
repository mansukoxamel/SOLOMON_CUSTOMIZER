6. 次の整理方針

対象方針理由
毎フレーム敵AI原則PRG0維持ステージ実行中のbank切替は事故リスクと負荷が高い。
敵IDごとの属性/見た目/挙動表PRG1またはロード時RAMコピー候補大きい固定テーブルはPRG0に置く必要が薄い。
ステージ開始前だけ必要な処理PRG1活用候補ロード時ならbank切替の安全設計がしやすい。
強化敵 wrapper共通化候補現在は敵ごとに似た判定/分岐が増えており、PRG0断片を消費している。

Panel Variant PRG0/PRG1 分解見積もり

項目Size扱い
現在のpackable blob全体274Bテスト用に一塊へまとめた値。最終配置そのものではない。
PRG1/RAM側へ逃がせる速度プリセット表8B固定データ。PRG0実行コードではないため、PRG1配置またはロード時RAM展開候補。
既存Panel系routine置換込みのPRG0純増見積もり164BBullet hookを既存hookへ統合する前提の現行見積もり。
速度プリセット表をPRG1/RAMへ逃がした後のPRG0純増見積もり156B現時点で確実に分離できるデータ8Bを除外した値。
既存PRG1 PanelVariantStageTable1,040B16B header + 64 rooms x 16B。A/B/Cの速度・間隔設定データ置き場。
既存PRG1 runtime loader86B / 予約96Bステージロード時にPRG1テーブルから $0740-$074F へコピーする処理。
