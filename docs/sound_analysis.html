Solomon's Key (NES) サウンドエンジン解析

解析日: 2026-05-11 / 出典: NSFファイル + USA ROM バイナリ逆解析 + ピアノ楽譜PDF照合
NSFファイル（4,256 bytes）とUSA ROM のバイナリ比較で99.2%一致を確認。
楽譜PDF（変ホ長調 = Eb major / C minor）との照合で音程マッピングを確定。
6502逆アセンブルでサウンドエンジンの内部構造を解明。
2026-06-04追記: 実ASM SUB_F190 / SUB_F235 を再確認し、 コマンド表を更新。旧メモの F8=transpose、F5=return、 F6=pattern end は誤り。現行解釈は F8=DUTY、 F4=RETURN、F5=LOOP_START、F6=LOOP_DEC_BNE、 F9=CHANNEL_END。
2026-06-04 MIDI照合追記: ユーザー提供 D:/DL/title-song.mid を ROM内1曲目 sound id $01 と照合。メロディtrackは $F650 と366/366音、ベースtrackは $F592 と352/352音が完全一致。 したがって音名変換（ノートbyte → C/D/E表記）はこの範囲で妥当。 長さはMIDI側のクオンタイズや 0x0C ホールド表現で揺れるため、音程一致を主根拠とする。

2. 音符バイトフォーマット

2-1. ノートバイト（0x00〜0x7F）

ビット配置:  [octave:4bit][semitone:4bit]

  上位4ビット = オクターブ番号（0〜7）
    ROM octave 0 = 実音 octave 2 (C2〜B2, 65〜123 Hz)
    ROM octave 1 = 実音 octave 3 (C3〜B3, 131〜247 Hz)
    ROM octave 2 = 実音 octave 4 (C4〜B4, 262〜494 Hz)
    ...

  下位4ビット = 半音番号（0〜11）
    0=C, 1=C#, 2=D, 3=D#(Eb), 4=E, 5=F, 6=F#, 7=G, 8=G#(Ab), 9=A, 10=A#(Bb), 11=B
    12(0x0C) = ホールド/タイ（直前の音程を維持して長さを足す）

3. コマンドバイト（0xF0〜0xF9）

バイト引数機能
F0 xx1バイトINSTRUMENT。$F39Aの音色プリセットポインタを選ぶ。
F1 xx1バイトVOLUME。channel state +5 の下位4bitを設定。
F2 lo hi2バイトJUMP。シーケンス位置を$hiloへ移動。主にループ。
F3 lo hi2バイトCALL。戻り位置を保存し、$hiloのパターンを再生。
F4なしRETURN。CALL元へ戻る。
F5 xx1バイトLOOP_START。ループ回数を保存し、直後の位置をループ先にする。
F6なしLOOP_DEC_BNE。回数を減らし、0でなければLOOP_START直後へ戻る。
F7 xx1バイトSWEEP。APU $4001 へ直接書き込む。
F8 xx1バイトDUTY。pulse波形デューティを設定。移調ではない。
F9なしCHANNEL_END。該当チャンネルを停止してシーケンス処理を抜ける。

4. トラック構造

4-1. 曲ポインタテーブル（$F47C）

26曲 × 2バイト（リトルエンディアン）のアドレステーブル。各エントリがトラックヘッダを指す。

4-2. トラックヘッダ形式

[ch_id] [ptr_lo] [ptr_hi]   ← チャンネル割当 + 楽曲データアドレス
[ch_id] [ptr_lo] [ptr_hi]   ← 2チャンネル目
...                          ← 最大8チャンネル

ch_id の最上位ビット(bit7): 先頭チャンネルフラグ
ch_id の下位ビット: チャンネル番号 (0〜7)
  偶数(0,2,4,6): パルス系チャンネル
  奇数(1,3,5,7): パルス2/三角波/ノイズ系

7. 編集可能性

改造内容難易度方法
音程を変える（ドレミ変更）★☆☆ 簡単ノートバイトを書き換えるだけ。上位4bit=オクターブ、下位4bit=半音。
テンポを変える★☆☆ 簡単デュレーションテーブル($F380)の値を変更。
音色を変える★★☆ 中F0/F1/F8コマンドのパラメータ変更、またはエンベロープテーブル編集。
曲の長さを変える★★★ 難パターン追加/削除はアドレスが変わるため、全ポインタ再計算が必要。
完全に新しい曲に差替え★★★ 難曲データ領域(約2.6KB)に収まる範囲で新規作曲+バイト列生成。
注意: 楽曲データ領域は約2,670バイトで26曲すべてが詰まっている。
曲を長くすると後続曲のアドレスがずれるため、単純な長さ変更は不可。
音程・テンポ・音色の変更は同一バイト数なので安全に改造可能。
