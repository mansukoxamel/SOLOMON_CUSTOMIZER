Panel Monster Full Design Map

Baseline: commit 61ef7c7 / JP mapper66 wide-title編集ROM。 この資料は、Panel Monster周辺を再実装する前に、原作処理・既存2-way/3-way・A/B/C Panel Variant・RAM/ROM配置・Bullet衝突契約を一枚で追えるようにするための設計図である。

0. 先に結論

今の問題は「Panel Monsterの全体像が一つの設計として固定されていない」こと。 実装は動作修正を重ねた層構造になっており、A/B/Cの速度・間隔を消す作業でも、Fire path、AI path、Bullet path、loader/cache、親物理guardのどこへ影響するかを毎回見失いやすい。

1. 対象範囲

原作Panel Monster
IDs $24-$27。Panel本体は方向を持ち、一定間隔でBullet $20-$23 を生成する。

Phase 1の目的: A/B/Cを「ステージごとに速度/間隔が変わる敵」ではなく、「敵IDだけでA/B/C種別と方向が決まるPanel Monster派生」として整理する。 そのため、PRG1 stage table、PRG1 global cache table、RAM $0740-$0745 cache、cache読込helperは削除候補になる。

7. 現在の問題点

問題1: A/B/C速度・間隔の保存経路が過剰
current 61ef7c7では、全ステージ共通の6B値をPRG1へ置き、loaderでRAMへコピーし、PRG0 helperがRAMから読む。 しかしPhase 1要件では「ステージ別A/B/C速度・間隔を廃止」するため、この経路は目的に対して重い。
問題2: cache helperが設計の中心に残っている
$BE62 interval helper、$BE9F group RAM offset helper、$BEBD speed selectorがcache前提。 これを残したまま「見た目だけtableを消す」と、再保存互換やMesen検証でズレる。
問題3: 親drift対策と共通物理の責務が曖昧
current 61ef7c7は $866D speed initializer hookで速度を消す。 ただし、どの段階で $8689 common physicsが走るかは別問題で、probeではここを明確に分けて見る必要がある。
問題4: Bullet markerの観測点を間違えると結論が崩れる
markerはchild sub-slot +7。main-slot +7 はY座標。 Mesen probeではこの区別を最初に固定する。

8. Phase 1設計

8.1 作業順

順番作業理由成功条件
1 この設計図を基準にする。 接続全体を固定しないままコードを削ると、loader/cache/Bullet/AIが混ざる。 どのhelperが何を読むか説明できる。
2 cache経路を廃止する設計を確定。 Phase 1の本体はPRG1 table/RAM cache依存の削除。 $0740-$0745 をPanel Variantが読まない。
3 interval/speed helperを直接値または固定契約へ置換。 cache helperを残すとPhase 1が完了しない。 $BE62/$BEBD/$E92C の責務がcache非依存になる。
4 runtime loaderからcache copyだけ削除。 StageExt/Seal/visible item side effectsは別機能なので残す。 loader再保存互換が維持される。
5 ROM/RAM管理簿と RESERVED_SPANS を同時更新。 空き領域誤認を防ぐ。 room_flags._verify() が通る。
6 Mesen probeで動作確認。 静的署名だけではBullet/親driftは確定しない。 旧cache writeなし、Bullet marker正、A/B/C方向正。

8.2 削除/維持マトリクス

項目Phase 1理由
A/B/C敵ID維持ユーザーが配置済みの敵種別を読めなくしてはいけない。
A/B/C speed/intervalのステージ別保存廃止Issue Phase 1の中心。
PanelVariantStageTable 64 room table廃止/予約回収ステージ別値が不要になる。
PRG1 6B global cache table廃止候補直接operand方式にするなら不要。

2-way/3-way borrowed IDs維持既存機能。A/B/C helperに巻き込まない。

Bullet extra step + $AC39維持壁抜け防止の核。
property/animation Panel classifier維持見た目をPanel Monsterにするため必要。

10.2 Pass 0で確定する不変条件

不変条件理由破ると起きる問題
Panel系IDは失わない。既存ステージデータの敵種別互換を守る。古いステージでA/B/C敵が消える。
ステージ別A/B/C speed/interval値は復元しない。旧仕様を延命しない。cache/table互換が残り、Phase 1が終わらない。
2-way/3-wayをA/B/C cache pathへ巻き込まない。既存強化Panel Monsterは維持対象。2-way/3-wayの弾数や方向が崩れる。
Bullet markerはchild sub-slot +7。speed preset判定の実体。main+7のY座標をmarkerと誤診断する。
速いBulletはsubstepごとに $AC39 を守る。壁抜け防止。2x/3x Bulletが壁をすり抜ける。
$0740-$0745 はPhase 4でPanel用途から外す。cache廃止は土台整理後に行う。loader/RAM/helperだけ先に変えて挙動がずれる。
