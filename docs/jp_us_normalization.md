# 日本版・US版オリジナルROM差分と正規化仕様

## 対象

- 日本版: `Solomon no Kagi (J).nes`、CRC32 `013ED497`
- US版: `Solomon's Key (USA).nes`、CRC32 `B7A00D99`、SHA-256 `81308ffe54c55508c143d04d0f5ef5e88e1da4d75483d8c43148011647fd0065`
- どちらも iNESヘッダ16バイト + PRG 32KiB + CHR 32KiB の65,552バイト

US版は別仕様のゲームではなく、日本版と同じゲームデータ・処理をブロック単位で再配置し、USライセンス画面とUSタイトル素材を加えた構成である。全53ステージについて、床、アイテム、敵、星座、ミラー、鍵、制限時間、開始位置、出口を意味単位で比較し、一致を確認した。

## 差分の概要

| 区分 | 差分 | 結論 |
|---|---:|---|
| iNESヘッダ | 3バイト | US版の予約領域値を消し、NES 1.0ヘッダへ正規化する |
| PRG | 15,190 / 32,768バイト | 大半はブロック再配置と、その移動に伴う絶対アドレス・分岐先の変更 |
| CHR | 996 / 32,768バイト | bank 3のUSタイトル素材が中心。US版からそのまま保持する |
| ステージ内容 | 53 / 53面一致 | JP用の既存ステージ読書き処理を共用できる |
| ボーナス配置 | 1バイト | 日本版 `$D2` に対しUS版 `$B2`。既存アプリも `$B2` へ補正しているためUS値を保持する |

CHR bank 1とbank 2は完全一致する。bank 0は最初のタイル内3バイトだけ異なる。bank 3は993バイト異なり、主にタイトル・メニュー表示である。

## USからJP論理配置へのPRG変換マップ

CPUアドレスは通常32KiB PRGを `$8000–$FFFF` に配置した時の値。終端は含まない。

| JP配置の出力範囲 | US配置の入力範囲 | 移動量 |
|---|---|---:|
| `$8000–$9497` | `$8000–$9497` | `0` |
| `$9497–$9589` | `$94A1–$9593` | `+$0A` |
| `$9589–$959E` | `$95F2–$9607` | `+$69` |
| `$959E–$9EA6` | `$961B–$9F23` | `+$7D` |
| `$9EA6–$9EBA` | `$9F0F–$9F23` | `+$69` |
| `$9EC0–$B3B1` | `$A000–$B4F1` | `+$140` |
| `$B3B1–$B3C0` | `$B4F1–$B500` | `+$140` |
| `$B3D0–$BBE2` | `$B800–$C012` | `+$430` |
| `$C200–$CB80` | `$C100–$CA80` | `-$100` |
| `$CB8D–$CBB1` | `$CADA–$CAFE` | `-$B3` |
| `$CBB1–$CBEA` | `$CB00–$CB39` | `-$B1` |
| `$CBEA–$CFDE` | `$CB41–$CF35` | `-$A9` |
| `$D000–$10000` | `$D000–$10000` | `0` |

JP側の `$BBE2–$C1FF` は1,566バイトすべて `EA` であり、USライセンス画面のデータ・処理はこの正規化先へ持ち込まない。ほかのJP空きも `EA` で復元する。`$B3B1–$B3BF` にはJP側の未参照断片を入れず、同じ処理の `RTS` 直後にあるUS側 `$B4F1–$B4FF` の `00/FF` パディング15バイトを保持する。US版に同形の処理が存在しないタイトル開始部だけは、ライセンス画面を通らずタイトル描画へ進む13バイトを `$CB80–$CB8C` に置く。

再配置後は、664個の16ビット絶対アドレス、2個の相対分岐、分割ポインタ表・即値・境界処理70バイトをJP配置へ直す。さらに、USライセンス再表示用の `$7C` bit 7処理を削除した後もStart/Selectでデモを終了できるよう、CPU `$CBEA` の1命令を `BMI` から直接判定の `BNE` へ変更する。正規化結果は全体SHA-256 `764ebf3bcfbff6f0b5e6e585705e562b60220c89a37c032758dfd18afcccda30` と照合し、一つでも漏れれば読み込みを失敗させる。

日本版由来値の監査結果は次のとおり。

- 直接指定する71バイトのうち70バイトは、再配置されたUS版のポインタ・分割アドレス・相対分岐距離である。
- 残る1バイトはCPU `$CBEA` の `BNE` 命令で、ライセンス再表示制御を削除したことに伴う論理変換である。
- JP側の未参照断片15バイト、著作権年 `1986` のtile値、JP IRQベクタは書き込まない。
- タイトル開始コード13バイト以外に、JP版のコード列を追加しない。

## 正規化後ROMと日本版原本の最終差分

US原本をJP論理配置へ正規化したmapper 3 ROMと、CRC32 `013ED497` の日本版原本を全65,552バイト直接比較した。差分は合計1,085バイトで、次に挙げる範囲だけである。これ以外のヘッダ、PRG、CHRはすべて一致する。

| 内容 | ファイルオフセット | CPU/CHR上の位置 | 実差分数 | 値・意味 |
|---|---|---|---:|---|
| US著作権年 | `0x1593` | CPU `$9583` | 1バイト | JP=`06`（1986）、US正規化後=`07`（1987） |
| ボーナス配置 | `0x1957` | CPU `$9947` | 1バイト | JP=`D2`、US正規化後=`B2` |
| USパディング | `0x33C1–0x33CF` | CPU `$B3B1–$B3BF` | 15バイト | USの `00/FF` パディングを保持 |
| タイトル属性 | `0x4D73` | CPU `$CD63` | 1バイト | JP=`9A`、US正規化後=`5A` |
| タイトル画面データ | 下記6範囲 | CPU `$CE1E–$CE89` 内 | 69バイト | USタイトル表示データ |
| US IRQベクタ | `0x800E–0x800F` | CPU `$FFFE–$FFFF` | 2バイト | JP=`EA EA`、US正規化後=`FF 00` |
| CHR bank 0 | `0x8019–0x801A`、`0x801F` | bank 0・tile 0内 | 3バイト | tile 0内の3バイト |
| CHR bank 3 | `0xF810–0x1000F` 内 | bank 3・local tile `$180–$1FF` | 993バイト | USタイトルロゴ用グラフィック |

タイトル画面データ69バイトの正確な連続差分範囲は次の6か所である。

| ファイルオフセット | CPUアドレス | 差分数 |
|---|---|---:|
| `0x4E2E–0x4E3C` | `$CE1E–$CE2C` | 15バイト |
| `0x4E44–0x4E4C` | `$CE34–$CE3C` | 9バイト |
| `0x4E58–0x4E5F` | `$CE48–$CE4F` | 8バイト |
| `0x4E69–0x4E76` | `$CE59–$CE66` | 14バイト |
| `0x4E7B–0x4E89` | `$CE6B–$CE79` | 15バイト |
| `0x4E92–0x4E99` | `$CE82–$CE89` | 8バイト |

CHR bank 3の `0xF810–0x1000F` は差分を含む最小の包括範囲であり、2,048バイト全部が異なるわけではない。この範囲内の実差分は993バイトで、67個の連続差分区間に分かれる。CHR bank 3の先頭6KiB `0xE010–0xF80F` は日本版と完全一致する。

完全一致を確認した領域は次のとおり。

- iNESヘッダ16バイト
- PRG全域のうち、上記89バイト以外
- 全53ステージの床、アイテム、敵、星座、ミラー、鍵、制限時間、開始位置、出口
- JPライセンス除外領域 `$BBE2–$C1FF` に対応するファイル `0x3BF2–0x420F` の1,566バイトすべて（両方とも `EA`）
- タイトルパレット
- CHR bank 1とbank 2の全域
- CHR bank 0の上記3バイト以外
- CHR bank 3の `0xE010–0xF80F`

したがって正規化後に日本版原本と異なる意味上の要素は、USタイトル表示データ、USタイトル画像、US著作権年、ボーナス配置の1バイト、USパディング、未使用のUS IRQベクタ、CHR bank 0・tile 0内の3バイトだけである。ゲームプログラム本体とステージ内容をUS配置のまま残した箇所はない。

## タイトルとライセンスの扱い

- USライセンス画面は捨てる。
- USタイトルのパレット、ネームテーブル、属性はUS原本のバイトをJP側のタイトル位置へ移す。
- CHRはUS原本の32KiBを丸ごと保持する。
- その後は既存のJP mapper66変換とwide-title正規化をそのまま実行する。
- アプリ内へUSタイトル画像そのものを同梱せず、ユーザーが読み込んだ原本からだけ取り込む。

## 対応範囲

初期対応はCRC32 `B7A00D99` とSHA-256が一致する確認済みUS原本だけとする。別CRC、改造済みUS ROM、古い生成物を推測で変換しない。正規化は読み込み直後、ステージ解析とmapper66変換より前に実行する。保存後の形式は従来どおりJP論理配置の mapper66 wide-title 拡張ROMであり、US配置のmapper66 ROMを新設しない。
