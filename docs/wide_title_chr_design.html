Wide Title CHR Design

ワイドタイトルのCHR使用範囲、保護範囲、PNG取り込み方針を整理する作業台帳。2026-06-21 時点では「修正前の現在地」として、現在実装がどのPRG/RAM/CHR領域を使い、どこを使ってよいと見なしているかを棚卸している。

重要: この文書は作業中の設計台帳。下の「自由に使えるCHR範囲マスター」に入った範囲は確定扱い。まだ入っていない範囲は、現在実装が使っていても自由領域とは見なさない。

1. アドレスの読み方

呼び方意味例
stream値ワイドタイトルストリーム内の1バイトtile値。タイトル描画では _BG_BASE = 0x100 を足してCHR物理タイルへ変換する。stream 0x30 => CHR tile 0x130
CHR物理タイルCHR bank内の0から始まる8x8タイル番号。スプライトビューアの「bank内」と同じ見方で会話する。bank内 0x130
ROMファイル範囲NESファイル先頭からのオフセット。iNESヘッダ16バイトを含む。bank内 0x130 => file 0x17310-0x1731F

4. Wideタイトル方式の定義

Wideタイトル方式は、自由に使えるCHR 154タイルを、タイトル画面上の任意154箇所へ割り当て、各8x8マスへ自由な字形・絵を置けるようにする方式。絵柄以外の配置、組み合わせ、色指定はPRG1側のデータで持つため、同じCHRをどこへ何回置くか、どの色で見せるかを柔軟に組み合わせられる。

項目定義
自由CHRリスト上の「自由に使えるCHR範囲マスター」の154タイルを正とする。以後の設計・実装・判断はこのリストを基準にする。
自由配置数画面上の任意154箇所
154個の前提この154個には、元の「ソロモンの鍵」タイトル絵で使っているCHRも含む。つまり元絵を壊して上書きしてよい前提なら154個を自由に使える、という意味。
誤解禁止元のタイトル絵をそのまま残した状態で、さらに別の場所へ追加で154個を自由に描ける、という意味ではない。
原画維持時の追加枠日本版オリジナルのタイトル画面を表示したまま、追加で何かを描きたい場合は、0x12C-0x197 の108個から既存タイトル絵が使う22マスを除いた86マスを自由に使える。
代表的な使用範囲x=6..23, y=6..13
代表範囲の意味タイトルロゴ差し替えで主に使いたくなる範囲としての目安。方式そのものをこの座標範囲に限定するものではない。
配置の考え方154個の自由CHRを画面上の154箇所へ1対1で当てれば、マス単位で独立した絵を持てる。配置先は固定枠ではなく、タイトル画面上の必要な場所を選べる。
CHR再利用同じCHRを複数マスへ配置することもできる。同じ絵を再利用した分だけ自由CHRに余裕が生まれ、その余りを別の新規絵へ回せる。
再利用時の色同じCHRを2か所に置いても、配置先の属性パレットが異なれば、それぞれ別の色で表示できる。
色制限NESのCHRは8x8タイル単位では4色まで。画面全体では複数パレットを使い、Wideタイトル全体として16色枠まで使えるという理解で扱う。
属性パレット単位背景の色指定は基本的に16x16px単位。同じ16x16属性ブロック内の8x8タイル4枚は同じ背景パレットを使う。
CHR側が持つ情報8x8の絵柄データのみ。
PRG1側が持つ情報絵柄以外の全情報。どの画面座標に、どのCHRを、どの組み合わせで置くか、どの属性パレットを使うかをワイドタイトル用データとして持つ。
方式の強み絵柄と配置・色を分離しているため、同じCHRを再利用したり、別の色で見せたり、任意位置へ組み合わせたりできる。
x=6..23, y=6..13 は、現在想定しているタイトルロゴ差し替えの中心範囲。自由配置154箇所の考え方自体は、この範囲に限定しない。

5. タイトル移植の対象と保証範囲

別ROMからタイトルを移植する機能は、元ROM側のタイトルデータを読み取り、このアプリのワイドタイトル方式へ移すためのもの。

項目方針
対象地域日本版、アメリカ版のどちらも対象。
対象mappermapper3、mapper66のどちらも対象。
拡張状態ワイドタイトル未拡張ROM、すでにワイドタイトル拡張済みのROMのどちらも対象。
現在の確認状況現時点で入手・確認できている日本版/アメリカ版、mapper3/mapper66、未拡張/拡張済みの各ROMは、滞りなく取り込める見込み。
移植先取り込んだタイトルは、このアプリのワイドタイトル方式の配置・属性・CHR絵として再構成する。
保証しない範囲移植元の拡張ROM自体が誤った作りになっている場合は保証しない。座標、配置、属性、CHR参照などが元ROM側で壊れている場合、その壊れ方までは救済対象にしない。

6. 現在コードのPNG取り込み判断

対象: magatu_skc/core/title_screen.py の apply_title_top_image_from_png()。

処理現在の内容
上部範囲タイトル上部行を top_cells として取り出す。
保護対象上部以外で使っているstream値を used_outside として集める。
候補選定range(0x30, 0x100) のうち、used_outside に入っていないstream値を available にする。
実質的な意味bank内 0x130-0x1FF のうち、下部や別領域で使っていないタイルを上部PNG用に再利用する。
問題になりそうな点: 「今のワイドタイトル画面で上部以外に使っていない」ことと、「自由に上書きしてよいCHRタイルである」ことを同一視している。修正時は、上のマスター表を基準にした固定のCHR所有権表へ寄せる。

10. 修正方針メモ

論点現状修正時に決めること
自由CHR範囲上の「自由に使えるCHR範囲マスター」を確定済み範囲として扱う。実装側のPNG取り込みやBUILD文字割当を、このマスター表と同じ定数へ移す。
保護CHR範囲bank内 0x100-0x12F は候補外。上部以外で使う 0x1A8, 0x1C0-0x1D0, 0x1D2-0x1DD も実行時に除外。BUILD文字、下部タイトル、固定部品、将来予約を所有者別に分ける。
PNG取り込み上部PNGの必要タイルを、候補poolから割り当ててCHRへ書く。固定poolだけへ書くのか、既存上部だけを再利用するのか、原作/US/ワイドタイトルごとに扱いを分けるのか決める。
会話上の基準スプライトビューアに bank内 表示を追加済み。今後は bank内 0x... で場所を指定して照合する。
