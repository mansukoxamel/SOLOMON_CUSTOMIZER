SOLOMON_CUSTOMIZER オブジェクト重なり仕様

キャンバス上で同じマスに複数のオブジェクトを置けるか、 置ける場合はゲーム開始時に何として見えるかを整理する。

現時点の主対象は、主人公スタート、鍵、扉、デーモンミラー1/2の重なり。 ここでは見た目を中心に書く。見えない要素も内部データとしては残る。

重なり可否マトリックス

行と列の要素を同じマスに置けるかを示す。

行＼列 主人公 鍵 扉 ミラー1 ミラー2
主人公 - ○ ○ ○ ○
鍵 ○ - ○ ○ ○
扉 ○ ○ - ○ ○
ミラー1 ○ ○ ○ - ○
ミラー2 ○ ○ ○ ○ -
記号意味
○同じマスに配置可能。
-同一種別同士。通常は1つの位置設定だけを持つ。
△条件付き、または挙動確認が必要。今後の追記用。
×同じマスに配置不可、または保存形式上成立しない。今後の追記用。

ゲーム開始時の見え方

主人公以外の 鍵、扉、ミラー1、ミラー2 は 背景側の要素なので、同じマスにあっても絵は1つだけ見える。

表示優先順位: 鍵 > 扉 > ミラー

鍵と扉とミラーが同じマスにある場合、ゲーム開始時に見えるのは鍵。 鍵が無い組み合わせでは扉が見え、扉も無い場合だけミラーが見える。

組み合わせ 同じマスに配置 ゲーム開始時に見えるもの
鍵 + 扉 可能 鍵
鍵 + ミラー 可能 鍵
扉 + ミラー 可能 扉
鍵 + 扉 + ミラー 可能 鍵
ミラー1 + ミラー2 可能 ミラー画像

主人公スタートの扱い

主人公スタートは別格。ゲーム中の主人公は動き回るキャラクターなので、 鍵、扉、ミラーの上に乗って表示される。

項目仕様
同じマスへの配置 主人公スタートは、鍵、扉、ミラーと同じマスに配置できる。
グラフィック 主人公は鍵/扉/ミラーの上に重なって表示される。
鍵との関係 主人公スタートと鍵が同じマスにある場合、ゲーム開始直後に鍵へ触れている状態になる。 鍵は取得対象なので、触れた時点で鍵を取る挙動になる。
キャンバス操作 同じマスに主人公、鍵、扉、ミラーがある場合、Ctrl+左ドラッグで掴む優先順位は 主人公 > 鍵 > 扉 > ミラー とする。

モンスター同士の重なり

検証済み 同じマスに複数のモンスターを配置できる。 ゲーム画面でもキャンバス上でも、モンスターリストの下にあるもの、つまりリスト順が遅いものほど手前に表示される。

組み合わせ 同じマスに配置 ゲーム開始時に見えるもの キャンバス操作
モンスター + モンスター 可能 モンスターリストで後ろにあるモンスターが手前に見える。 同じマスから掴む場合も、見えている手前側のモンスターを優先する。

主人公とアイテムの重なり

検証済み 主人公スタートとアイテムは同じマスに配置できる。 見た目はゲーム画面でもキャンバス上でも主人公が手前に表示され、ゲーム開始直後にそのアイテムを取得する。

組み合わせ 同じマスに配置 ゲーム開始時に見えるもの ゲーム開始直後の挙動
主人公 + アイテム 可能 主人公が手前に見える。 主人公がアイテムに触れているため、すぐ取得する。

主人公とモンスターの重なり

検証済み 主人公スタートとモンスターは同じマスに配置でき、見た目はゲーム画面でもキャンバス上でも主人公が手前に表示される。 ただし、ゲーム開始直後に主人公が死亡するため、SOLOMON_CUSTOMIZER上では危険配置として禁止する。

組み合わせ 実ゲーム上の重なり ゲーム開始時に見えるもの SOLOMON_CUSTOMIZERでの扱い
主人公 + モンスター 可能 主人公が手前に見える。 配置禁止。開始直後に死亡するため。

アイテム同士の重なり

検証済み アイテム同士は同じマスに複数配置しない。 同じマスに別アイテムを置く操作は、複数重ねるのではなく、そのマスのアイテムを置き換える扱いにする。

組み合わせ 同じマスに配置 ゲーム開始時に見えるもの SOLOMON_CUSTOMIZERでの扱い
アイテム + アイテム 不可 1つのアイテムだけ。 同じマスに置いた場合は既存アイテムを置き換える。

メタ要素とアイテムの重なり

検証済み メタ要素のうち、鍵・扉とアイテムは同じマスに配置しない。 ミラーとアイテムは同じマスに配置でき、表示上はアイテムが見える。

組み合わせ 同じマスに配置 ゲーム開始時に見えるもの SOLOMON_CUSTOMIZERでの扱い
鍵 + アイテム 不可 鍵が優先され、アイテムは成立しない。 配置禁止。
扉 + アイテム 不可 扉が優先され、アイテムは成立しない。 配置禁止。
ミラー + アイテム 可能 アイテムが見える。 配置可能。

メタ要素とモンスターの重なり

検証済み メタ要素とモンスターは同じマスに配置できる。 表示はゲーム画面でもキャンバス上でも、常にモンスターが手前に見える。

組み合わせ 同じマスに配置 ゲーム開始時に見えるもの SOLOMON_CUSTOMIZERでの扱い
鍵 + モンスター 可能 モンスターが手前に見える。 配置可能。
扉 + モンスター 可能 モンスターが手前に見える。 配置可能。
ミラー + モンスター 可能 モンスターが手前に見える。 配置可能。

アイテムとモンスターの重なり

検証済み アイテムとモンスターは同じマスに配置できる。 表示はゲーム画面でもキャンバス上でも、常にモンスターが手前に見える。

組み合わせ 同じマスに配置 ゲーム開始時に見えるもの SOLOMON_CUSTOMIZERでの扱い
アイテム + モンスター 可能 モンスターが手前に見える。 配置可能。

ブロック同士の重なり

検証済み ブロック同士は同じマスに複数配置しない。 1マスの地形値は1つだけなので、同じマスに別ブロックを置く操作は、そのマスのブロックを置き換える扱いにする。

組み合わせ 同じマスに配置 ゲーム開始時に見えるもの SOLOMON_CUSTOMIZERでの扱い
ブロック + ブロック 不可 1つのブロックだけ。 同じマスに置いた場合はそのマスのブロックを置き換える。

ブロックと他要素の関係

検証済み ブロック絡みは単純な重なりではなく、禁止または状態吸収として扱う。 ミラーだけは例外で、見た目はブロックになり、ミラーの機能だけが残る。

組み合わせ 同じマスに配置 ゲーム開始時に見えるもの SOLOMON_CUSTOMIZERでの扱い
主人公 + ブロック 不可 成立させない。 配置禁止。主人公がブロックに埋まるため。
モンスター + ブロック 不可 成立させない。 配置禁止。
アイテム + ブロック 状態吸収 ブロックが見える。 ブロック内アイテム状態として扱う。
鍵 + ブロック 状態吸収 ブロックが見える。 ブロック内鍵状態として扱う。
扉 + ブロック 状態吸収 ブロックが見える。 ブロック内扉状態として扱う。
ミラー + ブロック 可能 ブロックが見える。 ミラーの見た目は出ないが、機能は残る。ブロックの裏からモンスターが出る。
補足: ここで見えない要素も、内部的には消えていない。 ただし、この表では「何が見えるか」を優先して整理している。
